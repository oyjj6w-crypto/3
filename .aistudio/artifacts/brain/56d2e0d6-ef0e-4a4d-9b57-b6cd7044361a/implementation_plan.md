# 标签页独立快捷视窗组合预设方案

本方案根据用户明确要求，将顶栏 3 个快捷视窗组合按钮由“全局通用”升级为“**每个标签页（分组）完全独立隔离保存**”。每个标签页均拥有专属的快捷预设名称和视窗显隐配置，切换标签页时秒级加载对应专属配置，各标签之间互不干扰并持久化存储。

---

## User Review & Critical Decisions

> [!IMPORTANT]
> **已确认决策（标签页作用域与独立存储）**：
> 1. **独立数据隔离**：每个标签页（如“BTC主流”、“以太生态”、“山寨精选”或自建分组）独立维护属于该标签的 3 个快捷按钮（包括自定义文字标识与 W1/W2/W3 显隐勾选）。
> 2. **标签切换联动**：切换顶栏标签页时，这 3 个快捷按钮的文字和对应组合自动无缝切换为该标签的专属配置。
> 3. **初始缺省与回退机制**：对于新创建或尚未单独配置的标签页，自动提供标准的默认初始模板（预设1显示 W1、预设2显示 W1+W2、预设3显示全部 W1~W3），一旦长按自定义后即针对该标签持久化落盘。
> 4. **多端同步规范**：Web 端采用 `Record<string, WindowVisibilityPreset[]>` 按 `groupId` 分键存入 LocalStorage；Android 原生 Compose 端同步支持按当前标签的 `groupId` 隔离管理。

## 1. Overview & Core Concept

- **解决的核心痛点**：
  此前 3 个快捷预设为全局统一，交易员在“BTC主流”标签下可能希望预设为“大饼特写 / 永续与现货对比”，但在“公链三巨头”标签下希望预设为“SOL单屏 / ETH+SOL双拼”。全局统一会导致跨标签使用时命名和搭配受限。
- **核心价值**：
  1. **场景化定制**：每个交易策略标签页都拥有专属的看板切换方案；
  2. **零干扰隔离**：在标签 A 无论怎么改名或调整视窗显隐，标签 B、C 的配置均保持原样；
  3. **记忆化持久存储**：重新打开网页或重启应用，各个标签的专属预设完整复原。

[ 标签组: [BTC主流] [以太生态] [MEME热度] ] ── [ W1-W3 控制 ] ── [ ETH主图 · L2双拼 · 质押全览 ]
                                                              ▲ 瞬间切换为标签2的专属快捷按钮

### 关键用户流程 (User Flows)

1. **查看与切换**：
   - 用户点击顶栏不同的标签页，3 个快捷按钮的文字和显隐规则跟随标签即时变更；
   - 单击快捷按钮，立即按当前标签下的预设配置切换窗口显隐，并给出轻量级微光反馈。
2. **长按自定义与作用域说明**：
   - 用户在当前标签页长按任意快捷按钮，弹出配置对话框；
   - 弹窗顶部明确标注：`⚙️ 配置快捷按钮 #{id} - 当前标签: 【{当前标签名}】`；
   - 用户修改名称（如“大饼单图”）并勾选显示视窗，点击“保存并应用”；
   - **仅当前标签页**的该预设被更新并持久化，其他标签页中的预设完全不受影响。

## 3. Key Product Decisions & Trade-Offs

- **决策 1：存储结构设计**
  - *选择*：使用以 `groupId` 为键的字典对象结构 `Record<string, WindowVisibilityPreset[]>`。
  - *原因*：与原有 `WindowGroup` 分组数据解耦，既不破坏原有标签结构，又能针对每个标签独立索引与更新；若某个标签被删除，对应键值也能安全回收。
- **决策 2：删除标签页时的级联清理**
  - *选择*：当用户删除某个自定义标签页时，同步清理该标签对应的预设缓存，避免 LocalStorage 残留冗余脏数据。
- **决策 3：Android Compose 端同步保持一致**
  - *选择*：在 `TradingMultiViewScreen.kt` 与 `TradingViewModel.kt` 中，将预设管理改造为以当前激活的 `activeGroupId` 为依据的多字典映射。

## 4. Technical Architecture & Data Strategy

### 状态流架构图

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                                 App.tsx                                      │
│  - activeGroupId: string                                                     │
│  - tabGroupPresetsMap: Record<string, WindowVisibilityPreset[]> (LocalStorage)│
│    {                                                                         │
│      "preset_1": [ { id: 1, name: "大饼单图", visibleIds: [1] }, ... ],      │
│      "preset_2": [ { id: 1, name: "ETH主图", visibleIds: [1] }, ... ],       │
│      "custom_xxx": [ ... ]                                                   │
│    }                                                                         │
│  - currentTabPresets: useMemo(() => tabGroupPresetsMap[activeGroupId] || ...)│
└──────────────────────────────────────┬───────────────────────────────────────┘
                                       │
                 ┌─────────────────────┴─────────────────────┐
                 ▼                                           ▼
┌─────────────────────────────────┐        ┌──────────────────────────────────┐
│      Top Navigation Bar         │        │    PresetConfigModal (长按弹出)  │
│ 渲染当前标签的 3 个快捷按钮     │        │ - 显示当前隶属标签名称           │
│ - onClick: 应用当前标签组合     │        │ - 保存时仅写入当前 activeGroupId │
│ - onLongClick: 打开配置弹窗     │        │ - 校验至少保留 1 个视窗可见       │
└─────────────────────────────────┘        └──────────────────────────────────┘
```

### 核心数据模型

```typescript
// 按标签页分组隔离的快捷预设存储结构
export type TabGroupPresetsMap = Record<string, WindowVisibilityPreset[]>;
```

### 修改文件清单
1. **`src/types.ts`**：增加 `TabGroupPresetsMap` 类型声明；
2. **`src/App.tsx`**：
   - 改造 `windowPresets` 为基于 `activeGroupId` 的字典映射；
   - 切换标签时派生计算当前激活标签的 3 个预设；
   - 保存时精准写入当前标签并更新 LocalStorage；
   - 删除标签时级联清理对应预设；
3. **`src/data/androidProjectSource.ts`**：
   - 在 `TradingMultiViewScreen.kt` 中引入按 `activeGroupId` 隔离的预设管理字典，确保 Android 原生端行为一致。
